포트폴리오와 적용 후보

제안: 반복 업무 60% / 기존 방법 개선 30% / 새로운 실험 10%. 단일 작업 할당량이 아니며 실제 배분은 미측정이다.

  • 60% 반복 운영 안정화: upstream 동기화 provenance, source→dist 소유권, manifest/package/README 버전 일치. 반복성이 높고 실패 시 플러그인 전체에 영향이 크다.
  • 30% 기존 방식 개선: pstack의 stage 모델을 LazyZ의 ulw-plan→ulw-execute에 매핑하고, 단일 versioned Dispatch/Receipt contract를 둔다.
  • 10% 실험: 실제 ZCode lifecycle acceptance scenario와 post-merge observation contract. 호스트 차이 때문에 작은 범위로 시작한다.

재사용 workflow와 후속조치

  1. P0 — 재현 가능한 선택 동기화: ulw-loop spawn guard/admission/Stop 기능을 source adapter로 이식하거나, hash가 기록된 opaque runtime으로 명확히 고정한다. 둘을 혼합하지 않는다.
  2. P1 — 계약과 provenance: deprecated start-work가 아닌 독립된 versioned Dispatch/Receipt reference로 모든 skill 링크를 옮기고, 0.12.0 version·upstream 5.1.51 provenance를 package, manifest, README, vendor lock에 일치시킨다.
  3. P1 — 실제 surface contract: SessionStart, UserPromptSubmit, Pre/PostToolUse, Stop, local MCP와 누락 런타임 안내를 하나의 host lifecycle acceptance contract로 정의한다.
  4. P2 — 상태와 유지보수: Boulder/goals/ledger의 typed writer·shared parser·migration path를 설계하고, 반복 장애는 hook·fixture·skill rule에 기록한다.

제한: Codex 전용 thread/goal API, model TOML, installer config mutation, 무제한 continuation은 ZCode에 그대로 이식하지 않는다. LazyZ의 명시적 승인, privacy-default telemetry OFF, namespaced role, ZCode의 Stop 제한은 유지한다.

권한: 이 보고서는 제안만 한다. 설치·배포·업스트림 병합·외부 메시지·유료 호출 권한을 부여하지 않는다.
