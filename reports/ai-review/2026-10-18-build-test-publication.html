LazyZ 0.11.0 — 빌드·테스트 및 공개 검증

2026-10-18 KST · 대상: lazyz-github · 제품 경로: plugins/lazyz · 이번 요청: 전체 빌드·테스트, 발견 문제 수정, GitHub 커밋·푸시.

결과와 검증 한계

정의된 LazyZ 제품 검사 npm run check가 종료 코드 0으로 완료됐다. 테스트 1,385개, 12개 컴포넌트 타입 검사, ZCode 호환성 검사가 통과했다. 잠긴 의존성 감사는 0건이며 소스 없는 807파일 설치 묶음의 무결성 검사도 통과했다.

이 문서는 커밋 직전의 로컬 검증 기록이다. 원격 게시와 CI의 최종 상태는 GitHub Actions에서 해당 커밋과 연결해 확인한다. GitHub Release·홈페이지 배포·실제 ZCode 운영 검증을 의미하지 않는다.

판정 항목결과와 근거
로컬 구현·제품 검사완료 — check 종료 코드 0, 아래의 테스트 수와 설치 묶음 검사.
별도 상위 프로젝트 범위OmO 전체 Codex 설치기·중첩 Codex 플러그인은 미완료 범위. 전체 adapter 탐색 실행에서 17 실패(11 import 오류 포함)를 관찰했으며, 이를 통과로 집계하지 않았다.
로컬 테스트 부작용초기 LSP 테스트 격리 오류로 개발자 환경의 설치 승인 두 항목이 변경됐다. 확인 가능한 원본 한 항목은 복원했고 다른 항목은 사용자 선택이 필요하다. 이후 임시 경로 전용 검사에서는 추가 변경이 없었다. 구체적인 개인 설정 기록은 공개 저장소에 포함하지 않는다.
완전 완료 여부로컬 제품 검사 완료. 원격 CI와 개인 설정 후속 처리는 별도 상태이며 이 문서는 자동 완료로 간주하지 않는다.
실제 업무 개선개선 미검증 — 기능·의존성·테스트 경로는 확인했지만 생산성·비용·지연의 비교 실험은 하지 않았다.

이번에 수정한 문제

  1. 네이티브 process 훅의 실행 경로가 command가 아닌 args에 있는 경우 테스트가 놓치던 문제. bootstrap → CodeGraph 순서 조건은 유지했다.
  2. LSP 빌드가 잠금 설치 뒤 다시 패키지를 설치하던 경로를 제거했다. 의존성은 루트 npm ci로 준비하며, 없는 경우 오류를 낸다.
  3. 기존 실행 파일이 있으면 소스 변경을 무시하던 MCP 빌드를 고쳤다. 소스 checkout에서는 세 MCP bundle을 재생성하고, 소스 없는 설치에서는 prebuilt를 사용한다.
  4. CLI가 간접 의존성으로만 사용하던 esbuild를 직접 선언했다. Bun은 1.4.2로 고정했다.
  5. js-yaml 4.3.2, source-map-js 1.2.2, Vitest 4.1.11로 알려진 감사 항목을 처리했다. 감사 0건은 모든 보안 문제의 부재를 뜻하지 않는다.
  6. LSP 테스트에 명시적 요청 컨텍스트와 임시 home을 제공했다. 코어의 컨텍스트 없는 요청 거절·경로 제한을 유지했다. standalone MCP resource probe 호환 처리도 보완했다.
  7. Bun이 Markdown을 HTML로 변환하지 않도록 prompt import를 text로 지정했다.
  8. 상위 monorepo 경로에 묶인 테스트를 이동 가능하게 했다. 모델 자료는 원본 고정 커밋의 snapshot을 보존하고 공급자 ID와 snapshot 표기의 메타데이터 대응만 보완했다. 사용자 모델 선택·공급자 라우팅은 변경하지 않았다.
  9. /start-work를 승인된 기존 계획을 실행하는 /ulw-execute 계약과 통일했다.

실행한 검사와 범위

주 실행 환경: macOS, Node 26.5.0, npm 11.17.0, Bun 1.4.2. 설치 묶음 doctor/help는 Node 24.19.0에서도 확인했다. CI 정의는 Linux/macOS × Node 20/22이며 로컬 결과를 그 네 조합의 결과로 대신하지 않는다.

doctor는 기존 LSP daemon 상태와 다른 설치본을 가리키는 로컬 CLI 연결을 경고했다. 사용자 환경을 자동 변경하지 않았다. 실제 ZCode plugin discovery, 승인→실행 시나리오, 외부 MCP·CodeGraph provisioning, Windows, 유료 모델 호출은 이번 검증에 포함되지 않았다.

제품 범위와 별도 상위 설치기 테스트는 게시 가이드에 명시했다. 초기 실패 로그를 지우거나 skip으로 감추지 않았으며, 제품에 포함되는 helper 6파일은 별도로 실행했다.

재사용 후보와 후속조치

반복 공개가 있을 때마다 잠금 설치 → 소스 재빌드 → 제품 gate → 별도 설치 묶음 검사를 사용하는 후보가 있다. 매 release마다 수행할 가능성이 높다는 추정이며 실제 빈도는 기록하지 않았다. 실패 시 게시를 중단하고 소스를 고친 후 관련 검사를 다시 수행한다. 전역 설치·모델 호출·비밀정보 변경은 포함하지 않는다.

회복은 이후 Git revert로 수행할 수 있다. import 도구는 대상 전용 파일을 삭제하지 않으며, 덮어쓰기 전 임시 백업을 만든다. docs/reports/source-snapshot.json은 10월 17일 가져온 원본의 해시 목록이지 이번 수리 후 최종 파일의 해시 목록이 아니다. 최종 변경은 Git 이력, CLI provenance, export manifest로 추적한다.
