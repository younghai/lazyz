# Why

코드의 **동기와 의도**를 조사한다. `how`가 "무엇을 하는가"라면 `why`는 "무엇이 이 모양을 만들었는가"를 답한다. 코드는 하는 일만 보여줄 뿐 존재 이유는 보여주지 않는다. 이유는 커밋·PR·이슈·문서·회고에 흩어져 있고 불완전하다. 그 불완전함을 숨기지 않고 등급으로 드러낸다.

출처: cursor/plugins pstack v0.15.25 (MIT, poteto)의 why 스킬을 ZCode 환경(git + gh + 로컬 문서·증거)으로 축소 포팅. 원본은 MCP로 sentry·datadog·slack 등 7개 증거 원천까지 조사한다.

## 자세

신중하고 정확한 조사자. 아는 것과 추론하는 것을 구분해 말한다. 모든 주장은 아래 등급 중 하나에 놓인다.

1. **직접(Direct)** — 저자가 직접 쓴 문구가 이유를 말한다. PR 본문("1000개 이상 페이징 실패 수정"), 이슈("고객 보안 리뷰 요청"), 코드 주석("// 상游 API가 더 큰 값을 거절해서 100으로 클램프"), 설계 문서. 표현: 확신, 현재형, 인용.
2. **지지(Supported)** — 직접 문구는 없지만 간접 증거 여러 개가 수렴한다. 표현: "증거가 X를 강하게 가리킨다: [항목들]".
3. **추론(Inferred)** — 맥락의 합리적 읽기이나 명시적 지지는 없음. 내 해석이다. 표현: "A와 B가 있으니 C일 가능성이 높아 보인다(근거 D)".
4. **추측(Speculative)** — 얇은 증거 위의 가설. 다른 설명도 같은 정도로 맞는다. 사용자가 판별할 수 있으니 제시하되 가설임을 밝힌다. 표현: "~일 수 있지만 동시대 증거는 못 찾았다".

등급을 못 정하겠으면 낮은 쪽으로. 빈 결과도 결과다("PR 본문이 비어 있었다"를 기록한다).

## 1단계 — 대상과 질문 확정

대상은 보통 코드 조각·패턴·기능·이름 붙은 설계 결정. 질문은 보통 설계 사유·트레이드오프·동기가 된 엣지 케이스·외부 제약·죽은 코드·역사 스윕. 대상이 모호하면 열린 파일·최근 편집·직전 대화에서 최선의 해석을 정하고 한 줄로 밝혀 진행한다(사용자가 틀렸으면 정정하게).

## 2단계 — 코드 앵커 (인라인, 조사 전에)

모든 조사자에게 건넬 씨앗 컨텍스트를 먼저 직접 만든다:

- 파일 경로와 줄 범위, 핵심 심볼(함수·클래스·상수).
- `git log --follow -p -- <file>` — 이름 변경까지 전체 이력.
- `git blame -L <start>,<end> <file>` — 마지막 터치 커밋.
- `git log --oneline -20 -- <file>` — 최근 커밋과 PR 번호(`(#1234)` 패턴).
- `git log -1 --format=%B <sha>` / `git show <sha>` — 커밋 전문.
- `gh pr view <n> --json title,body,author,mergedAt,labels,closingIssuesReferences,comments,reviews` — PR 본문·토론. 원격이 없는 로컬 저장소면 이 단계를 건너뛰고 커밋 메시지만 쓴다(건너뛰었다고 말한다).

## 3단계 — 병렬 조사 (Agent 스폰)

기본은 전체 병렬 조사. 커버리지 맵이 목적이다. 한 번에 여러 Agent 콜로 돌린다(읽기 전용 `Explore`나 `lazyz:explorer`). 조사자당 증거 원천 하나:

1. **커밋·코드 이력** — 대상이 생겨난 커밋과 그 전후 커밋. 이웃 커밋이 같은 사건을 다루는지.
2. **PR·이슈(gh)** — 원격이 있으면 `gh pr list/--search`, `gh issue list --search "<키워드>"`. 원격이 없으면 null 기록.
3. **로컬 장문 문서** — 저장소의 docs/, 설계 문서, RFC, README, CHANGELOG. `.omo/plans/`, `.omo/drafts/`에 계획 의도가 남아 있는 경우도 많다.
4. **로컬 증거·회고** — `.omo/evidence/`, QA 로그, decisions.tsv, 운영 이력(admin changelog 등). 과거 사건·되돌림·재발의 흔적.
5. **테스트·코드 자체의 암시** — 추가된 테스트가 지키는 값, 매직넘버와 대응하는 표준(SLA·제한), 이름이 암시하는 의도. (직접 등급은 못 되지만 지지·추론의 재료.)

각 조사자에게 앵커를 그대로 넘긴다. 원본 문구를 인용해 오게 한다(요약만 보내지 않게). 각각 "찾은 인용 + 등급 후보 + null 결과 명시"를 반환.

## 4단계 — 종합

하나의 답으로 합친다. 규칙:

- 답의 각 주장에 등급을 붙이고, 직접 인용은 출처(커밋 sha, PR #n, 파일:줄)와 함께 제시.
- 증거가 서로 충돌하면 둘 다 보여주고 충돌을 지적(숨기거나 임의로 선택하지 않는다).
- "왜"에 대한 기록이 아예 없으면 그렇게 말한다. 부족한 등급의 추측으로 채우지 않는다.
- 마지막에 한 줄: 이 기록이 지금 어떤 결정에 걸려 있는지(예: "이 사유가 더 안 유효하면 X를 삭제해도 된다").

**응답:** 등급별로 정리된 조사 브리프. 인용은 출처와 함께. 150단어 요약이 먼저, 증거 전체는 뒤에.
