## UC-01: 자연어 task로 코드 변경 요청

| 항목 | 내용 |
|---|---|
| 액터 | 개발자 |
| 설명 | 개발자는 자연어로 "이 버그를 고쳐줘", "이 기능을 구현해줘" 등 task를 입력한다. |
| 사전 조건 | 프로젝트가 열린 상태, 필요한 model provider가 설정됨 |
| 기본 흐름 | 1. 개발자가 task 입력<br>2. Orchestrator가 Plan Agent 호출<br>3. Plan Agent가 코드베이스 탐색<br>4. 실행 계획 생성 및 사용자에게 제시<br>5. 사용자가 승인<br>6. Execute Agent가 순차 실행<br>7. Verify Agent가 검증<br>8. 결과 보고 |
| 예외 흐름 | E1. 계획이 모호하면 사용자에게 질문<br>E2. 실행 중 실패하면 디버깅 budget 내 재시도<br>E3. 계속 실패하면 human escalation |
| 후 조건 | 코드 변경 완료, ledger에 기록, evidence 첨부 |

## UC-02: 긴 작업 중 context compaction으로 지속

| 항목 | 내용 |
|---|---|
| 액터 | 개발자, xcode harness |
| 설명 | 대화/로그가 길어져 context 한도에 도달하면, Compaction Engine이 현재 목표를 기준으로 필요한 기억만 남기고 agent를 재개한다. |
| 기본 흐름 | 1. context 임계치 도달 감지<br>2. Compaction Engine 호출 (현재 task 목표 전달)<br>3. dedup → tool-aware reduction → summarization → hard cap<br>4. 압축된 working memory로 agent 재개<br>5. agent는 중단 지점부터 계속 실행 |

## UC-03: Multi-agent 협업으로 복잡한 task 해결

| 항목 | 내용 |
|---|---|
| 액터 | 개발자, planner/executor/reviewer/qa agent |
| 설명 | 복잡한 task는 여러 specialist agent가 협업하여 처리한다. |
| 기본 흐름 | 1. Orchestrator가 task 난이도 평가<br>2. 필요한 agent 조합 결정<br>3. Planner → Executor → Reviewer → QA 순으로 handoff<br>4. 검증 실패 시 이전 단계로 되돌림<br>5. 최종 결과 보고 |

## UC-04: Graph Workflow로 동적 처리

| 항목 | 내용 |
|---|---|
| 액터 | 개발자, 시스템 |
| 설명 | task 유형/위험도/검증 결과에 따라 동적으로 workflow 분기가 실행된다. |
| 기본 흐름 | 1. task 분류 (단순/복잡/위험)<br>2. 단순: 바로 execute<br>3. 복잡: research → plan → execute → verify<br>4. 위험: human approval gate<br>5. verify 실패: 다시 execute |
