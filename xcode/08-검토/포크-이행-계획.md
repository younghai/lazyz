# 포크 이행 계획 — `impl/` 처분

pi 를 포크한 뒤 6주간 만든 `impl/` 을 어떻게 정리하는가.

판단 기준은 하나다 — **pi 가 이미 더 잘하는 것은 버리고, pi 에 없는 것만 남긴다.**
이건 3주차에 정한 기준(`남겨야 될 것은 명백한 value add 여야 한다`)을 그대로 적용한 것이다.

각 항목은 grep 으로 확인했다. 느슨한 grep 이 오탐 둘을 냈고 걸러냈다 —
`classify` 는 read 툴의 무관한 단어였고, `checkpoint` 는 요약 프롬프트의 단어였다.

---

`@xcode/ai` 프로바이더 5종도 버린다 — pi 는 45+ 를 갖고 있고 우리 것보다 넓다.

## 확장으로 이식한다 — pi 에 없다 (약 1,600줄)

| 모듈 | 줄 | 상태 | pi 에 없는 근거 |
|---|---|---|---|
| **human gate** | — | ✅ 이식 완료 | `grep -r human_gate` 무소득. pi 는 의도적으로 권한 시스템 없음 |
| **scrubber** | 195 | ⬜ | `grep -riE "redact\|scrub\|mask.*secret"` 무소득 |
| **checkpoints** | 317 | ⬜ | `grep -rl "restoreFile\|rollback"` 무소득. 파일 롤백이 없다 |
| **working-memory** | 277 | ⬜ | 목표·결정·실패를 컴팩션 너머로 보존 |
| **planner** | 305 | ⬜ | 계획 생성 + 항목 추적 (pi 의 plan-mode 는 예제 확장) |
| **classify** | 185 | ⬜ | 위험 3-way 분류 → 라우팅 |
| **audit** | 183 | ⬜ | 감사 로그 |
| **verify** | 139 | ⬜ | 독립 검증 (테스트·린트·타입) |

이식 순서는 **pi 에 없는 정도 × 사고 시 피해**로 정한다:
`scrubber` → `checkpoints` → `verify` → `classify` → `working-memory` → `planner` → `audit`.

시크러버가 첫째인 이유: 시크릿이 세션 파일에 한 번 들어가면 되돌릴 수 없다.

## 그대로 옮긴다 — 측정 규율

| | 이유 |
|---|---|
| `bench/` (run.mjs · tasks.mjs · baseline.json) | CLI 를 **서브프로세스로** 띄우고 검사기가 자체적이다. spawn 명령만 바꾸면 그대로 돈다. 태스크 9개가 각자 독립 검사기를 갖는다 |
| `dogfood.sh` | pi 레이아웃에 맞게 손봐야 하지만 **접근법이 자산**이다 — F4·F5·F6 을 이것이 찾았고 벤치 픽스처로는 영원히 안 보였다 |
| `08-검토/` 기록 | 6주간 무엇이 왜 틀렸는지. 같은 실수를 다시 하지 않기 위한 유일한 장치 |

## 남는 질문

- **의존성 0개 주장은 끝났다.** pi 는 패키지 전반에 45+ 런타임 의존성을 갖는다.
  `packaging.test.ts` 의 그 검사는 의미가 없어졌다. 대신 지킬 것은
  **공급망 정책**(`ignore-scripts` · `min-release-age`)이고, 그건 pi 도 갖고 있다.
- **`--json` 프로토콜 계약.** 우리가 만든 handshake·command_result 는 pi 의
  `--mode json`/`rpc` 와 형식이 다르다. 호스트 연동을 다시 할 때 pi 쪽으로 맞춘다.
- **웹 소개 페이지**는 그대로 유효하다. 다만 "런타임 의존성 0개" 문구는 거짓이 됐다.
