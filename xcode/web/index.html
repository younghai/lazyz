01 / 흐름

한 세션 안에서 계속 말한다

한 번 실행하고 죽는 도구는 업무에 붙지 않는다. 대화가 이어지고, 실행 중에도 끼어들 수 있고, 언제든 되돌릴 수 있어야 한다.

  • xcode대화가 시작된다. 요청을 적으면 분류 → 계획 → 실행 → 검증이 돈다.
  • 실행 중 입력다음 턴에 반영되는 스티어링이 된다. 슬래시 명령은 절대 모델에게 가지 않는다 — 도구에게 한 말과 모델에게 한 말은 섞이지 않는다.
  • esc진행 중인 작업을 멈춘다. 멈출 방법이 없으면 사람은 도구를 두려워한다.
  • /diff이번 세션에서 에이전트가 고친 파일. /rollback 으로 되돌린다.
  • /review src/auth.ts저장소가 .xcode/commands/ 에 정의한 명령. 팀 전원이 같은 리뷰를 돌린다.
02 / 컨텍스트

컨텍스트를 비용으로 다룬다

창이 차는 것은 사고가 아니라 예정된 사건이다. 임계값 하나로 잘라내면 필요한 것까지 사라진다 — 그래서 5단계 사다리로 내려가고, 각 단계가 무엇을 잃는지 스스로 말한다.

03 / 안전장치

조용히 일어나면 안 되는 일들

각 장치는 이벤트 구독이 아니라 경계에서 붙는다. 구독으로 붙이면 다른 경로가 그것을 지나치고, 그때 아무도 알아채지 못한다.

human gate

위험하면 멈춘다

스키마 마이그레이션 · 파괴적 작업 · 배포는 사람이 답하기 전까지 진행하지 않는다. 답할 사람이 없으면 거부로 닫는다.

scrubber

시크릿은 들어가기 전에 가린다

컨텍스트와 세션 파일에 닿기 전에 가린다. 코드를 시크릿으로 오인하지 않는다 — contextTokens 를 가리면 에이전트의 인식이 틀어진다.

rollback

고친 파일을 되돌린다

디스크에 append-only 로 기록한다. 사람이 그 뒤에 손댄 파일은 건드리지 않는다.

project trust

저장소가 마음대로 지시할 수 없다

clone 한 저장소의 AGENTS.md 나 .xcode/commands/ 는 승인 전까지 로드되지 않는다. 읽기 전에 묻는다.

sandbox

작업 디렉터리 밖으로 못 나간다

문자열이 아니라 실제 경로로 판단한다. 심링크로 빠져나가는 경로를 실측으로 찾아 막았다.

verify

끝났다는 말을 믿지 않는다

테스트·린트·타입을 우리가 돌려서 판정한다. 실패하면 그 이유를 들고 구현 노드로 되돌아간다.

04 / 실측

이 페이지의 숫자는 전부 잰 값이다

11개 태스크 × 3회 = 33 시도. 검증은 에이전트의 자기 보고가 아니라 독립 검사기가 한다.

완료율≥ 70%100%33/33 시도
검증 통과율≥ 80%100%30/30 (테스트가 있는 시도)
평균 개입≤ 3회0.09총 3회
위험 라우팅 정확도100%100%11/11
컴팩션 3회 이내 완료≥ 80%100%33/33
crash rate< 2%0%없음
secret 노출0건0건세션 JSONL · stdout 검사

모델 변동이 1/33 수준으로 존재하고, 벤치는 그것을 회귀와 구분하지 못한다. 기준을 낮추지 않았다 — 초록으로 만들려고 검사를 약화시키는 것은 하지 않는다.

05 / 연동

IDE 를 얹을 수 있다

xcode --json 은 버전이 붙은 양방향 JSONL 계약이다. 첫 줄이 handshake 이고, 이벤트 40종과 명령 5종을 스스로 설명한다.

xcode --json
→ {"type":"protocol","version":1,"agent":"0.1.0","events":[…40종],"commands":[…5종]} → {"type":"human_gate_open","request":{"title":"위험 작업으로 분류되었다", …}} ← {"id":"h1","cmd":"gate","choice":"approve"} → {"type":"command_result","id":"h1","cmd":"gate","ok":true}

SDK 를 in-process 로 안으면 같은 이벤트를 그대로 받는다 — --json 은 그것을 프로세스 경계 너머로 옮긴 것뿐이다. --mode rpc 로 양방향 제어도 된다.
