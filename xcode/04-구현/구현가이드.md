## 1. 개발 환경

### 1.1 요구사항

| 항목 | 버전 |
|---|---|
| Node.js | 23.6.0+ (Gondolin 등 일부 extension 요구) |
| Bun | latest (standalone binary build용) |
| TypeScript | 5.x |
| Rust | 1.80+ (Tauri bridge) |
| Git | 2.x |

### 1.2 로컬 셋업

```bash
git clone https://github.com/.../xcode.git
cd xcode
npm install --ignore-scripts
npm run build
```

pi 스타일 개발:
```bash
# 소스에서 xcode 실행 (임의 디렉토리에서 실행 가능)
./xcode-test.sh
```

### 1.3 일반 커맨드

| 커맨드 | 용도 |
|---|---|
| `npm run build` | model data refresh 후 전체 패키지 빌드 |
| `npm run build:offline` | 기존 model data로 네트워크 없이 빌드 |
| `npm run check` | lint, format, type check (커밋 전 필수) |
| `./test.sh` | 전체 테스트 (LLM 의존 e2e 제외) |
| `./xcode-test.sh` | 소스에서 xcode 직접 실행 |

> pi의 가이드처럼 `npm run build`나 `npm test`는 사용자가 요청할 때만 실행한다. 커밋 전에는 `npm run check`와 `./test.sh`를 통과해야 한다.

## 3. 코딩 표준

### 3.1 철학

> **xcode core is minimal.** core에 속하지 않는 기능은 extension으로 만든다. core를 비대하게 만드는 PR은 거절된다.
>
> **You must understand your code.** AI로 코드를 짜는 것은 괜찮지만, 이해하지 못한 채 제출하는 것은 안 된다.

### 3.2 TypeScript

- `biome` 또는 `eslint` + `prettier` for lint/format
- strict TypeScript
- `Type` from `typebox` for tool parameters
- `no any` unless absolutely necessary
- Inline single-line helpers that have only one call site
- Check `node_modules` for external API types; don't guess
- **No inline imports** (`await import()`, `import("pkg").Type`, dynamic type imports). Top-level imports only.
- Use only erasable TypeScript syntax (Node strip-only mode) in `packages/*/src`, `packages/*/test`, `packages/coding-agent/examples`: no parameter properties, `enum`, `namespace`/`module`, `import =`, `export =`
- Never hardcode key checks (e.g. `matchesKey(keyData, "ctrl+x")`). Add defaults to `DEFAULT_EDITOR_KEYBINDINGS` or `DEFAULT_APP_KEYBINDINGS`
- Never modify `packages/ai/src/models.generated.ts` directly; update `packages/ai/scripts/generate-models.ts` and regenerate

### 3.3 Monorepo

- Internal workspace packages: version-ranged
- Direct external dependencies: pinned exact versions
- `package-lock.json` is the ground truth
- `.npmrc`:
  ```
  save-exact=true
  min-release-age=2
  ```
- Pre-commit blocks accidental lockfile changes unless `XCODE_ALLOW_LOCKFILE_CHANGE=1`
- `packages/coding-agent/npm-shrinkwrap.json`로 transitive deps 고정

### 3.4 Security

- Never commit secrets
- `auth.json` created with `0600`
- Package installs use `--ignore-scripts` by default
- Lifecycle scripts require explicit allowlist review
- Direct external deps는 exact version으로 pinned

## 4. 구현 패턴

### 4.1 새로운 Provider 추가

```typescript

export function myProvider(): Provider {
  return {
    id: "my-provider",
    api: "openai-completions",
    baseUrl: "https://api.example.com/v1",
    models: [...],
  };
}

// 등록

const models = createModels();
models.setProvider(myProvider());
```

### 4.2 새로운 Tool 추가

```typescript
// packages/coding-agent/src/tools/my-tool.ts
import { Type } from "typebox";

export const myTool: AgentTool = {
  name: "my_tool",
  description: "Does something useful",
  parameters: Type.Object({ path: Type.String() }),
  executionMode: "parallel",
  async execute(toolCallId, params, signal, onUpdate, ctx) {
    const result = await doSomething(params.path);
    return {
      content: [{ type: "text", text: result }],
      details: { path: params.path },
    };
  },
};
```

### 4.3 새로운 Extension 추가

```typescript
// ~/.xcode/agent/extensions/my-extension.ts
import type { ExtensionAPI } from "@xcode/coding-agent";

export default function (pi: ExtensionAPI) {
  pi.on("tool_call", async (event, ctx) => {
    if (event.toolName === "bash" && event.input.command?.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("Dangerous!", "Allow rm -rf?");
      if (!ok) return { block: true, reason: "Blocked by user" };
    }
  });
}
```

## 5. Supply-chain Hardening

> pi-coding-agent의 보안 철학을 따른다.

| 항목 | 규칙 |
|---|---|
| 기본 설치 | `npm install -g --ignore-scripts @xcode/cli` |
| 개발 설치 | `npm install --ignore-scripts` |
| CI 설치 | `npm ci --ignore-scripts` |
| package 설치 | pinned npm version 또는 git tag/commit |
| lockfile | `package-lock.json` / `npm-shrinkwrap.json`이 ground truth |
| lifecycle scripts | 보안 리뷰 후 allowlist 등록 |
| 의존성 감사 | `npm audit --omit=dev`, `npm audit signatures --omit=dev` |
| offline mode | `XCODE_OFFLINE=1`로 startup network 작업 비활성화 |
| self-update | `xcode update --self`로 마이그레이션 |
| reproducible build | CI에서 lockfile 기반 빌드 및 checksum 검증 |
| pre-commit | lockfile 변경 차단 (`XCODE_ALLOW_LOCKFILE_CHANGE=1`로 해제) |

## 6. 빌드 및 배포

### 6.1 개발 빌드

```bash
npm run build         # refresh model data, build all packages
npm run build:offline # existing model data, no network
npm run check         # lint, format, type check
./test.sh            # run tests
```

### 6.2 Standalone Binary

```bash
./scripts/build-binaries.sh --offline-model-data --platform linux-x64 --out ./out
```

### 6.3 Release Smoke Test

```bash
npm run release:local -- --out /tmp/xcode-local-release --force
```

smoke test 항목:
- `/tmp/xcode-local-release/node/xcode --help`
- `/tmp/xcode-local-release/node/xcode --version`
- `/tmp/xcode-local-release/node/xcode --list-models`
- `/tmp/xcode-local-release/node/xcode -p "Say exactly: ok"`
- Bun binary 동일 항목
- interactive mode는 tmux에서 실행 확인

### 6.4 Release 절차 (Lockstep Versioning)

- 모든 패키지는 동일한 버전을 공유
- `patch` = fixes + additions, `minor` = breaking changes, no major releases
- `/cl` prompt로 CHANGELOG `[Unreleased]` 감사 후 실행
- release script:
  ```bash
  XCODE_ALLOW_LOCKFILE_CHANGE=1 npm_config_min_release_age=0 npm run release:patch
  ```
- CI가 npm trusted publishing (GitHub Actions OIDC)

## 7. Git 규칙

### 7.1 Commit

- Only commit files YOU changed in THIS session.
- Stage explicit paths: `git add <path1> <path2>`
- Never `git add -A` / `git add .`
- Before committing, run `git status` and verify only your files are staged.
- Commit message format: `{feat,fix,docs}[(ai,tui,agent,coding-agent)]: <message>`
- Close issues: `fixes #1, fixes #2` (repeat keyword per issue)

### 7.2 Never Run

- `git reset --hard`, `git checkout .`, `git clean -fd`, `git stash`
- `git add -A`, `git add .`, `git commit --no-verify`
- force push

### 7.3 Rebase Conflicts

- Resolve conflicts only in files you modified.
- If a conflict is in a file you did not modify, abort and ask the user.

## 10. Containerization

pi의 containerization 문서를 참고하여 다음 패턴을 지원한다.

| 패턴 | 격리 대상 | 사용 예 |
|---|---|---|
| Gondolin extension | built-in tools, `!` commands | host에서 xcode 실행, 도구만 VM으로 라우팅 |
| Plain Docker | whole xcode process | 단순한 로컬 격리 |
| OpenShell | whole xcode process | policy-controlled sandbox (filesystem, network, credential, inference) |

xcode IDE/CLI는 기본적으로 host 권한으로 실행되며, 강한 격리가 필요하면 위 패턴 중 하나를 선택한다.
