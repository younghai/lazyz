## 1. 배포 전략

| 구성 요소 | 배포 방식 | 비고 |
|---|---|---|
| `@xcode/ai` | npm package | LLM provider abstraction |
| `@xcode/agent-core` | npm package | Agent loop, session tree, compaction, tool registry |
| `@xcode/coding-agent` | npm package | Built-in coding tools, planner, classify, verify |
| `@xcode/tui` | npm package + Tauri binary | Terminal UI library |
| xcode CLI | `npm install -g --ignore-scripts @xcode/cli` | pi 스타일 단일 패키지 배포 |
| xcode Desktop IDE | GitHub Releases (Tauri updater) | 자동 업데이트 |
| xcode Core Engine | Docker image / 내장 바이너리 | IDE에 번들 또는 별도 서비스 |
| Backend Services | Docker Compose / Kubernetes | 팀/클우드 버전 |
| Skill Marketplace | 별도 마켓 서버 | code signing 필수 |
| xcode Packages | npm registry / git tag | pinned refs, `--ignore-scripts` |

## 4. Release 절차

### 4.1 Lockstep Versioning

- 모든 `@xcode/*` 패키지는 동일한 버전을 공유
- `patch` = fixes + additions
- `minor` = breaking changes
- major releases 없음

### 4.2 Release 전 준비

- `/cl` prompt로 각 패키지 `CHANGELOG.md`의 `[Unreleased]` 섹션 감사 및 업데이트
- local smoke test:
  ```bash
  npm run release:local -- --out /tmp/xcode-local-release --force
  cd /tmp
  /tmp/xcode-local-release/node/xcode --help
  /tmp/xcode-local-release/node/xcode --version
  /tmp/xcode-local-release/node/xcode --list-models
  /tmp/xcode-local-release/node/xcode -p "Say exactly: ok"
  /tmp/xcode-local-release/bun/xcode --help
  # interactive mode는 tmux에서 실행 확인
  ```

### 4.3 Release 실행

```bash
XCODE_ALLOW_LOCKFILE_CHANGE=1 npm_config_min_release_age=0 npm run release:patch
# or
XCODE_ALLOW_LOCKFILE_CHANGE=1 npm_config_min_release_age=0 npm run release:minor
```

release script는 다음을 수행:
- 모든 패키지 버전 bump
- CHANGELOG 업데이트
- release artifact 재생성
- `npm run check`
- `Release vX.Y.Z` 커밋 및 `vX.Y.Z` 태그
- 새 `[Unreleased]` 섹션 추가
- `main`과 태그 push

### 4.4 Trusted Publishing

- CI의 `publish-npm` job이 GitHub Actions OIDC를 통해 npm trusted publishing 수행
- 로컬 `npm publish`, `npm whoami`, OTP 불필요
- 태그 push 시 `.github/workflows/build-binaries.yml` 트리거

### 4.5 실패 시

- publish helper는 idempotent: 이미 npm에 존재하는 버전은 skip
- CI publish 실패 시 태그 workflow 재실행, 동일 버전의 release script는 재실행하지 않음

## 5. Supply-chain 설정

### 5.1 .npmrc

```
save-exact=true
min-release-age=2
```

### 5.2 Lockfile & Shrinkwrap

- `package-lock.json`이 dependency ground truth
- `packages/coding-agent/npm-shrinkwrap.json`으로 transitive deps 고정
- pre-commit은 lockfile 변경 차단 (`XCODE_ALLOW_LOCKFILE_CHANGE=1`로 해제)
- shrinkwrap 생성 스크립트: `node scripts/generate-coding-agent-shrinkwrap.mjs --check`
