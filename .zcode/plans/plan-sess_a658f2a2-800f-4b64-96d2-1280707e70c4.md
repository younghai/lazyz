# Tier 2.6 계획: teammode 경량 포팅 (ZCode Agent tool 기반)

브랜치: `feat/tier2-teammode-light-port` (main 기반)

## 핵심 설계 결정

ZCode `Agent` tool은 **fire-and-forget-per-turn** (한 번 호출 → 최종 메시지 반환, mid-flight messaging 불가). 따라서 upstream teammode의 thread/live-messaging 모델을 그대로 옮길 수 없고, 아래처럼 매핑합니다:

| upstream (Codex) | lazyz (ZCode) |
|------------------|---------------|
| `codex_app.create_thread` per member | `Agent` tool call per member (`run_in_background: true`) |
| `bind-thread` (thread id 기록) | 불필요 — 제거 |
| `codex_app.send_message_to_thread` (live) | 불가 — 각 member의 **최종 메시지가 deliverable**. leader가 취합 |
| member-to-peer messaging | `artifacts/` 디렉토리로 비동기 파일 교환 |
| `threadId`/`threadTitle` 필드 | 제거 → `runId`(선택적 Agent 호출 추적용)로 대체 |
| worktree 격리 + merge 통합 | **그대로** (git 기반, harness 무관) |

## 파일 구성

### 1. 상태 모듈 3개 (vendor에서 복사 + ZCode 적응)
`plugins/lazyz/components/teammode/scripts/` 에 배치:

- **`team-state.mjs`** — vendor 것을 기반으로 `threadId`/`threadTitle`/`threadTitleConvention` 필드와 `bindThread`/`assertTeamReadyForThreadBinding`/`assertUniqueMemberThreadTitle` 제거. `addMember`는 `threadId: null, threadTitle: ...` 대신 `runId: null`만 남김. 나머지(lock, persistence, validateTeam, worktree 상태)는 그대로.
- **`team-worktree.mjs`** — **vendor 것을 100% 그대로 복사** (harness 무관, zero-dep).
- **`team.mjs`** (controller CLI) — vendor 것 기반, 핸들러 정리:
  - 유지: `init`, `add-member`, `member-prompt`, `set-status`, `worktree-add`, `worktree-remove`, `integrate`, `archive`, `delete`, `status`, `guide`
  - 제거: `bind-thread` (thread 개념 없음)
  - `add-member`/`status`/`worktree-add` 출력에서 thread/codex:// 링크 제거

### 2. guide 렌더러
- **`team-guide.mjs`** — vendor 것 기반, 통신 규칙 섹션을 ZCode 현실로 재작성:
  - `codex_app.send_message_to_thread` → "최종 메시지에 모든 결과/발견/`WORKING:` 단계를 포함해 leader에게 반환"
  - `codex://threads/<id>` 링크 → 제거
  - member-prompt: "Agent tool로 호출됩니다. guide.md를 읽고 작업한 뒤, 최종 메시지로 deliverable을 보고하세요"

### 3. 스킬 (탑레벨 직접 커밋)
- **`plugins/lazyz/skills/teammode/SKILL.md`** — ZCode Agent tool 중심으로 새 작성:
  - frontmatter: `name: teammode`, description에 트리거 문구 ("team of agents", "multi-agent collaboration", "parallel members")
  - leader 프로토콜: 메인 세션 = leader, code 작성 금지, orchestration만
  - member 정의: focus/lens/deliverable/name (vague job title 금지)
  - 최소 2명 (MIN_MEMBERS=2)
  - dispatch: `team.mjs init` → `add-member` (각 member마다) → 각 member를 `Agent` tool로 `run_in_background: true` 호출 (한 턴에 전부). prompt는 `team.mjs member-prompt` 출력 + 작업 컨텍스트
  - 취합: 각 Agent의 최종 메시지 = deliverable. `artifacts/`로 파일 교환
  - worktree 격리: 파일 충돌 시 `worktree-add` → member별 git worktree. `integrate`로 merge
  - AGENTS.md tooling map 준수 (Agent tool 사용법)

### 4. AGENTS.md 업데이트
- `teammode skill → depends on Codex thread API` 문구를 `teammode skill → ZCode Agent-tool-based lightweight port`로 변경
- tooling map의 `team_*(...)` 행 업데이트

## 빌드/등록
- teammode는 `.mjs` 스크립트 + SKILL.md만이라 **빌드 불필요** (dist 없음, node 직접 실행)
- `team.mjs`는 SKILL.md에서 `node "${PLUGIN_ROOT}/skills/teammode/scripts/team.mjs" <subcommand>`로 호출
- workspaces 등록 불필요 (TypeScript 컴포넌트가 아님)
- sync-skills.mjs 건드리지 않음 (탑레벨 직접 커밋이므로)

## 검증
1. **상태 모듈 단위 테스트** (bun으로 .mjs 직접):
   - `init` → team.json 생성, `add-member` 2회 → members 배열, 중복 focus/name 거부
   - `withTeamLock` 직렬화 (동시 mkdir 방지)
   - validateTeam가 thread 필드 없이 통과
2. **worktree 모듈**: 임시 git repo에서 `addMemberWorktree` → `integrateMemberBranch` (merge --no-ff) end-to-end
3. **controller CLI**: `node team.mjs init ... && node team.mjs add-member ... && node team.mjs status` 파이프라인
4. **SKILL.md frontmatter**: 파싱 정상, 트리거 문구 포함

## 커밋 구조
단일 커밋: `feat(teammode): add lightweight ZCode Agent-tool-based team collaboration port`

## 의도적 스킵/제약 (SKILL.md와 AGENTS.md에 명시)
- **live member messaging 불가**: ZCode Agent는 한 번 호출 → 최종 메시지 반환. mid-flight re-tasking은 새 Agent 호출 필요
- **PostToolUse thread-title hook 제거**: ZCode가 `create_thread` 안 씀
- **bind-thread 제거**: thread 개념 자체가 없음
- **단일 모델(GLM-5.2)**: 모든 member가 같은 모델. tier 구분 없음

## 위험
- team-state.mjs의 `threadTitle` 제거 시 `validateTeam`/`addMember`/`assertTeamReadyForThreadBinding` 얽힘 → 제거 후 unique-name/focus invariant만 남겨서 스키마 일치 유지
- SKILL.md가 leader에게 git worktree/merge를 직접 손으로 하라고 하면 안 됨 — 반드시 `team.mjs worktree-add`/`integrate` 서브커맨드만 쓰도록 명시
