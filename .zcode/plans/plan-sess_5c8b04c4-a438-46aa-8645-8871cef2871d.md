# 빌드 의존성 복원 계획 (수정된 접근)

## 문제 진단
`vendor/` 디렉토리가 이미 12개 의존성 패키지를 포함하고 있어 **외부 submodule 없이도 빌드가 가능한 구조**였습니다. 하지만 제가 Phase 5에서 빌드 시스템을 과도하게 수정/제거해서 빌드 체인이 깨졌습니다.

## 핵심 원칙 (교정)
**빌드 시스템은 upstream 원본을 최대한 보존**하고, ZCode 특화 변환(manifest, hooks, 변수명)만 적용합니다. 제가 제거/재작성한 스크립트들을 upstream 원본으로 되돌립니다.

## 작업 항목

### 1. 스크립트 복원 (upstream 원본 기준)
재clone한 upstream(`/tmp/lcx3`가 비워졌으므로 재 clone 필요)에서 다음 파일들을 원본대로 복구:
- `sync-skills.mjs` — 제 재작성 버전 폐기, 원본 복원 (단 teammode 매핑 제거, `.zcode-plugin` 경로만 수정)
- `materialize-shared-upstreams.mjs` — 복원 (frontend skill용, lazyz에 shared-skills 없으면 no-op 처리 확인)
- `sync-version.mjs` — `defaultRepoRoot`/`manifestTargets` 수정 폐기, 원본 복원 후 `.zcode-plugin` 경로만 유지
- `sync-hook-status-messages.mjs` — `.zcode-plugin` 경로 수정은 유지, `readAggregateHookPaths`는 원본 로직 복원
- `auto-update*.mjs`, `install-flow.mjs`, `spawn-command.mjs`, `entry-guard.mjs` — 복원
- `migrate-codex-config*`, `migrate-omo-sot*` — 복원 (auto-update가 import)

### 2. package.json 복원
- `dependencies`에 `"@oh-my-opencode/shared-skills": "file:../../shared-skills"` 복원
  - 단 lazyz엔 shared-skills가 없으므로 → `file:./vendor/shared-skills`로 변경하거나, shared-skills를 vendor에 추가
  - **검증 필요**: upstream에서 shared-skills가 어디서 오는지 (src/packages/shared-skills인데 lazyz엔 없음)
- `workspaces`에 `components/bootstrap` 추가 유지
- build 체인 원본 복원

### 3. shared-skills 의존성 해결 (핵심 미해결)
upstream의 `@oh-my-opencode/shared-skills: file:../../shared-skills`는 `plugins/lazyz/../../shared-skills` = lazyz repo root의 `shared-skills/`를 가리킴. 이건 oh-my-openagent의 패키지.
**옵션 A**: `src/packages/shared-skills`를 lazyz `vendor/shared-skills`로 복사하고 package.json을 `file:./vendor/shared-skills`로 변경
**옵션 B**: sync-skills.mjs가 shared-skills에서 frontend skill을 복사하는 부분을 제거 (frontend skill은 이미 materialize되어 있으므로)

### 4. node_modules 처리
lazyz에 `node_modules/`가 생성된 것을 발견 (.gitignore에 이미 포함). 커밋에서 제외 확인.

### 5. 실제 빌드 검증
bun이 설치되어 있으므로:
```bash
cd plugins/lazyz
bun install
bun run build  # 또는 node가 필요한 스크립트는 bun으로 실행
```
빌드 성공 후 `dist/` 생성 확인.

### 6. Codex 호환 블록 주입 로직 (sync-skills.mjs)
원본 sync-skills.mjs는 component에서 skill 복사 시 "Codex Harness Tool Compatibility" 블록을 주입함.
**수정**: 이 블록을 "ZCode Harness Tool Compatibility" 버전으로 교체한 채로 복사되도록 sync-skills.mjs의 `codexHarnessToolCompatibility` 템플릿과 `insertCodexCompatibilityGuidance` 함수 수정.

## 순서
1. upstream 재 clone
2. 원본 스크립트들을 lazyz로 복사 (ZCode 변환만 적용)
3. shared-skills 의존성 해결
4. `bun install && bun run build` 실제 실행
5. 빌드 성공 확인
6. hooks.json의 `${ZCODE_PLUGIN_ROOT}` 변수 정상 동작 확인
7. 그 후 GitHub push 진행

## 위험
- shared-skills 의존성 해결이 관건. frontend skill이 이미 materialize되어 있으므로 옵션 B(복사 로직 제거)가 단순할 수 있음
- 일부 스크립트가 node를 필요로 할 수 있음 (bun으로 대체 가능한지 확인 필요)
- 이 작업 후에도 ZCode 실제 설치 테스트는 별도 필요
